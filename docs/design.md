### 補充觀察 ─ 首頁推薦卡的媒體互動

- 「你可能會喜歡」部分商品卡的主圖下有多個圓點。依實際操作觀察，可按住主圖並向左或右拖曳來切換照片。圓點顯示當前媒體位置。
- 部分商品卡的主圖中央有播放鍵。點擊會開啟帶有背景遮罩、YouTube 播放器與關閉控制的彈層。截圖中的影片擁有者禁止站外播放，播放器顯示無法播放及「在 YouTube 上觀看」入口。
- 如擴充這些功能，將多圖與影片描述建模為可選的商品媒體。共用卡片的媒體區可依資料提供輪播或播放入口。張數、影片來源與目前瀏覽位置都不需要新增商品卡型態，瀏覽位置也不需要寫入展示設定。

## 技術與資料流

```text
Catalog + Registry → Showroom React state → ProductCard → 共用結構 + Variant presentation
                           ↑  ↓
                    v2 localStorage

Hosted HTML → mountMerchantCard(container, props) → 同一個 ProductCard
```

- 選 React、TypeScript、Vite 與 CSS Modules。React 統一總覽、編輯器與預覽資料流。TypeScript 的 discriminated union 表達商品的業務差異。CSS Modules 讓宿主可載入卡片樣式。代價是嵌入 bundle 隨附 React runtime。
- `kind` 描述業務情境，`layout` 描述排列。typed preset registry 只列可用路由和版型。用多款商品驗證共用邊界後，仍可保持靜態註冊。
- 商品名稱、售價及促銷文案由商品目錄、定價或活動來源提供。作業用 catalog 模擬來源。編輯器管理哪些區塊會顯示。React state 是當前分頁的有效展示設定。
- 依商品 ID 儲存 `{ version, settings }`，相同商品的方格及橫列共用。讀取驗證版本及欄位，舊版展示偏好會保留，舊版商品覆寫不生效。無效 JSON 或未知版本會回退預設，讀取本身保留原值。寫入失敗時保留分頁內狀態並提供可見提示。跨分頁同步留待後續。
- `sample.html` 以 JS module 和 CSS 載入同一 React 元件。宿主傳入資料快照，因此使用情境可重現。實際部署用靜態檔，沒有伺服器端狀態。

## 編輯器的責任邊界

真實電商的商品名稱與媒體通常由商品目錄提供，售價由定價服務計算，促銷文案和條件由活動系統提供，配送與庫存各有資料來源。Showroom 消費這些結果。本次以本機 catalog 模擬，不接後端。

| 類型 | 可調整內容 | 理由 |
| --- | --- | --- |
| 本次可編輯 | 促銷文案與橫幅的顯示、原價、評價、名次、銷量、剩餘組數、配送及活動標籤 | 切換區塊的可見性，驗證同一資料能套用不同呈現需求。每個卡片只提供適用的開關 |
| 可考慮增加 | 卡片密度、標題行數、主圖留白方式，或拆開促銷橫幅與促銷文案開關 | 這些都是可獨立測試的呈現決策。有第二個實際使用情境時，再把它們加入設定 |
| 預覽工具 | 預覽寬度與搜尋方格／橫列 | 用來比較不同容器寬度與版型。預覽寬度為上限，依中欄可用空間向下收縮。商品的顯示偏好沿用同一 ID |
| 固定在商品資料 | 商品名稱、媒體來源、售價、促銷條件、排名與庫存數值、配送承諾 | 由上游提供真值。畫面可以在允許的情境隱藏輔助區塊，資料數值由來源負責 |
| 隨資料固定呈現 | 主售價、廣告標記、起價或券後價等價格限定語意 | 讓使用者正確理解商品與價格。促銷成立條件影響顯示價格時，應隨價格同時呈現 |

## 優先順序與演進

P0 先讓搜尋方格走完導覽、單卡調整、持久化、正式建置嵌入與提交。P1 用同商品的橫列檢查跨 layout 一致性，再用排行及限搶驗證業務欄位擴充。多出來的 UI 保留為商品卡範圍內的預覽寬度控制與示意 CTA。

照片輪播、影片彈層、hover 操作、登入、真實購物車、API、倒數、商品詳情與動態 plugin loader 在原定交付範圍外。若擴充媒體互動，輪播需支援滑鼠、觸控與鍵盤，影片彈層需可關閉並提供外部觀看入口。當新卡片需要新增業務資料時，先擴充 `Product` union 和 variant adapter。等到有外部資料供應商時，再加入 runtime product schema。等到有多分頁編輯需求時，再定義事件同步、衝突規則和舊資料遷移。
